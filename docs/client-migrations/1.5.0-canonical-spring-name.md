# Client migration: 1.5.0 canonical Spring name

Backend 1.5.0 makes a Spring's official `name` canonical across languages while
keeping `description` localized. Existing URLs and response models remain
compatible.

## Recommended client change

Send Flutter's full device language tag to map, search, detail, and preview:

```dart
final locale = Localizations.localeOf(context).toLanguageTag();
```

```http
GET /api/springs/map?bbox=14.2,49.9,14.6,50.2&locale=en-AU
GET /api/springs/search?q=ostruzna&locale=en-AU
GET /api/springs/<documentId>?locale=en-AU
```

The parameter remains optional. Existing clients that omit it continue to work
through the dynamic Strapi default and per-document source-locale fallback.

## Detail locale fallback

Continue passing the device locale to the full detail endpoint when localized
description content is desired:

```http
GET /api/springs/<documentId>?locale=en-US&populate[photo]=true
```

The backend resolves a whole Spring document in this order:

1. exact configured tag (`en-AU`),
2. configured parent/base variants (`en`),
3. configured variants of the same language (`en-US`, `en-GB`, …),
4. the current Strapi default locale,
5. the document's source locale (`cs` for ČHMÚ).

The existing `data.locale` field identifies the locale actually returned. If
the requested localization exists with `description: null`, that localization
is returned unchanged; the server does not borrow a description from another
locale.

Map, search, and `/preview` use the same order. Collection endpoints choose one
whole published row per `documentId`; they never combine fields across rows.

## Compatibility guarantees

- Endpoint URLs are unchanged.
- Map and search remain `{ "data": [...] }`; result fields, alphabetical/proximity
  ordering, `limit`, and optional `distance_m` are unchanged.
- Full detail remains the standard Strapi `{ "data": ..., "meta": ... }`
  response and continues to support `fields`, `populate`, and `status`.
- Existing Spring and Report JSON field names are unchanged; no new required
  response field was added.
- `/api/springs/:documentId/reports` and its pagination contract are unchanged.
- `/api/platform-config` is unchanged.

## Recommended rollout

Release a client that consistently passes `toLanguageTag()` to localized Spring
reads. Older installed clients remain functional because `locale` is optional.
